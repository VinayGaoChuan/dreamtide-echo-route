# 余烬：迷航 Embers: Lost Voyage（仓库沿用旧名“梦潮：回声航线”）

胖乎乎的横版自动射击刷宝游戏（HTML / Canvas，目标平台 Steam：键鼠 + 手柄 / Steam Deck）。
一张地图是三关连打，一关是一串主目标，局内靠升级仪式长出这一局的构筑；精英和首领掉暗黑 2 式的装备（白 / 蓝 / 黄 / 绿套装 / 暗金），首领倒下货舱把东西送回家。
出击之间回到空间站：换装、卖、拆、改造台、赌博、仓库、保险舱，设施按做过的事打开；打通一张地图站里多一样东西（策划 [docs/design.md](docs/design.md) §6–§8）。

在线游玩：https://vinaygaochuan.github.io/dreamtide-echo-route/

## 操作

| 操作 | 键鼠 | 手柄 |
|---|---|---|
| 移动 | WASD / 方向键，或按住鼠标拖动（Shift 慢速） | 左摇杆 / 十字键 |
| 射击 | 自动开火，子弹固定向右 | 同左 |
| 大招 | 空格 | A（任意主按钮） |
| 暂停 | Esc | Start |

存档保存在各自浏览器的 localStorage（key `dreamtide.echo-route.v3`，里面是第 4 版存档，老存档打开时自动迁移）。

## 本地运行

不需要安装依赖，也没有构建步骤：

- 直接用浏览器打开 `index.html`；或者
- 在仓库根目录起一个静态服务：`python3 -m http.server 8000`（Windows：`py -3 -m http.server 8000`），再打开 http://localhost:8000/

## 站（出击之间）

出击回来先到空间站：飞船靠港，货舱里的东西进仓库（满了进到货区）。常驻信息只有信用点 / 废料 / 晶片 / 核心、驾驶员等级和出击按钮；点站上亮着的设施才展开面板。规则全在 `js/station.js`，数值在 `js/gear.js`，设计在 docs/design.md §6–§8。

- **死了带回什么**：首领倒下时货舱把已捡的东西送回家，从此安全；半路死了只丢本关新捡的白 / 蓝 / 黄，套装和暗金一定带回，保险舱（可升级）再保住最好的几件；信用点、材料、经验全带回。
- **设施按做过的事打开**：第一次回家开仓库、商人、保险舱、改造台；第二次开拆解台；攒到 500 信用点开黑市；驾驶员 5 级开机库。升级设施花信用点和材料；打通地图只开新内容（下一张图 + 站里多一样东西）。
- **卡关**：回去刷、地图偏某几族掉落、黑市按位赌、路标（从走到过的关直接出发，补发正常数量的升级仪式）、首杀和连空保底、能量 / 动能对护盾 / 装甲的软克制。

## 联机（2–4 人：合作 / 对抗）

依据是 [docs/design.md](docs/design.md) §9（原 v0.11）。**联机优先级高于策划文档**：哪份文档缺了联机部分，实现时自己补全。

**玩法**：大厅点「联机」→ 创建房间或加入别人的房间 → 房主选「合作」（再选关）或「对抗」、点开始。房间里每人显示真实成长（生命 / 攻击倍率 / 大招容量 / 驾驶员等级）。每人开自己的飞机、穿自己的装备（装备算成的属性随名单带给每一端），**局内各有一套**：
- **升级**：同一轮升级全队同时开始（v0.11 §7）：全场进入安全减速（敌弹化掉、贴脸的敌人推开、不刷怪、敌人不开火、计时停住），各选各的（主炮 / 支援 / 大招改造 / 联动 / 流派都是自己的），候选只在自己屏幕上；选好的人停在“✓ 选好了 · 等队友”，在线的都选好了一起继续。选的时候按大招键 = 选推荐（能凑联动 > 升级已有的 > 第一个；不会自动替你选）。倒下的人等救起后再补选；离开的人不拖住全队。
- **掉落**：每次掉落每人各一份，只有自己看得见、吸得到；自己机型和自己联动带来的额外掉落只给自己。
- **资源**：星砂、宝箱、碎片、升级次数各记各的，结算时各领各的。连杀、击破数是全队的。
- **倒下**（v0.11 §8）：残骸周围出现宽救援圈（`RESCUE`，world.js），队友飞进圈里停约 2 秒就地救起，回约 40% 生命、约 2 秒保护；**不会自动复活**；救援圈里的敌弹会化掉。在线的人全部倒下才算失败。

**掉线与重连**（v0.11 §8 / §13）：帧同步没有单一权威，名单里第一个在线、不在“断线中”的人负责判定（房主走了下一位接手）。
- 连接卡死：每秒一次心跳，3.5 秒收不到回包（或连上 3.5 秒还没拿到名单）就换一条新连接，身份不变；只收到服务器的完整名单之后才算连上，重连途中不判别人掉线（防“脑裂”）。
- 意外断开（关网、断线、关页面）：约 1.5 秒后所有人从同一帧起把他当“断线中”——飞机原地占位，不动、不开火、不受伤、敌人不瞄、不拖住全队升级和救援判定，拖着的矿核 / 吊舱转成大家都能接手；其他人照常继续。
- 60 秒内回来：按大家认定的操作记录追上（他那边要是按自己的操作多算过几帧，就换一个新世界从开局重算一遍，期间静音、显示“正在追上队友”），然后发“准备好了”，负责判定的人宣布从第 R 帧起恢复。操作记录整局保留。
- 超过 60 秒没回来：留出 3 秒提前量，从同一帧起移除。主动点“退出联机”的人直接移除，不占席位。
- 测试：`node tools/mp-sim.js js 1-2 3 net 0.1 100 5 '1@2000~900'`（1 号断网 30 秒，`0@…` 是房主断网，`vs` 也行），断言断网期间其他人照常推进、回来后状态一致；`node tools/net-bot.js … --dark=1@40~30` / `--host-leave=60` 走真实 WebSocket。
- 刷新页面：本标签页记着联机身份、房间和局号（sessionStorage），刷新后自动回到原房间；那一局还在打就以原身份回去（先请大家把自己判成断线中、新建世界按操作记录从开局追上，再恢复），分数、生命、Build 都保留，结算只发一次。房间列表里自己那一局显示“回到对局”。房主在房间里刷新，其他人等 8 秒不解散。测试：`net-bot … --reload=1@50`。
- 断线中的人头上和队友栏显示剩余席位秒数；超时后各端都显示“断线超过 60 秒，按退出处理”，对抗结算标出来。

同一局只结算一次（存档里的 `mpLedger` 记着结算过的局号）。

**房间**：成员要点“准备”（对房主当前的配置号确认；房主改玩法 / 关卡 / 属性或开过一局，准备自动作废），都准备好房主才能开始；开始有 3 秒倒计时，房主可以取消，有人取消准备也会自动取消。房间里直接列出这个玩法的完整规则；战斗中按 H 在自己飞机另一半屏弹出同一份规则卡，不暂停、不挡操作。
**升级限时**：联机选升级合作 25 秒、对抗 15 秒，到时自动选推荐（`CHOOSE_LIMIT`，offers.js）；自己和别人头上都有倒计时。

**对抗**（`js/vs.js`，v0.11 §11，自由竞争 2~4 人）：每人一条航道，三段各约 2 分钟。每段：清怪攒小分 → 第 14 秒左右每条航道出一座风塔（三只厚甲守卫），清掉拿目标分（本段第一个再加一点）→ 风塔变成两个干扰洞口，飞进一个把「矿甲列阵」或「侧风」送给分数最高的对手（先预兆再生效，每条航道同时最多一个强干扰、后来的排队；防守方处理掉也有分）→ 第 80~106 秒冲突区开放：航道交界那条红色带子里主炮能打到对手（同一人打同一人有命中间隔、累计到一颗心才扣、扣完短暂无敌）。被击毁约 3 秒后在自己航道原地复归，保留 Build、扣有限的分。升级每段两次、全场一起选，计时暂停。三段打完按分数排名（同分比清塔数，再同分平局）。分数有账本（`V.parts`：击破 / 风塔 / 送干扰 / 防守 / 压制 / 被击毁），结算逐项列出、合计正好等于总分，并指出和对手的分差主要来自哪一项。房主可选“统一属性”（所有人 1 级基础属性、大招容量 1）或“真实成长”（默认，按 v0.11；差距摆在房间里）。结算：参与 + 清塔 + 胜利（有限）信用点——参与奖要有效参与（打完；主动退出至少打满一段；掉线被移出打满 1 分钟），不算关卡进度。数值都在 `VS`（vs.js 顶部）。
**掉落**：合作时每人各掉各的一份（用自己的随机数，不进状态哈希），蓝 / 黄 / 绿可以在站里送朋友，暗金和改过的不行。联机时公开按人数加厚：大型敌人血量 ×(1 + 0.6 × (人数 − 1))，Boss ×(1 + 0.7 × (人数 − 1))。暂停菜单不会冻结联机战斗，只是自己的飞机原地不动。

**同步方式：帧同步，只发操作**。每秒 30 个操作帧，每帧推进 4 个模拟步（1/120 秒）；每人每帧只发 5 个字符（方向、慢速、大招、拖动），各端用同一个种子、同样的操作各自模拟同一局，不发游戏状态。本机操作晚几帧生效（网络缓冲默认“自动”：房主按房间里最慢两人的延迟定帧数；也可以手动选短 / 中 / 长），用来盖住网络延迟；连联机服务器时，大家按服务器时钟在同一刻开局，延迟不会全压在一个人身上；对局中缓冲还会跟着延迟自动加长 / 缩短（每人按“自己的延迟 + 最慢队友的延迟”算操作提前量）；自己的飞机按已经发出的操作先在画面上走（显示预测，不改模拟），手感不被缓冲拖慢；服务器只转发变化的字段（对局中基本只有操作帧），慢线路也不会越积越慢；凑不齐某一帧所有人的操作就等（画面提示“等待 XX 的操作…”）。每 30 帧各端交换一次状态哈希，对不上会提示。

**改玩法代码必须守的规则**（否则联机会分叉，`tools/mp-sim.js` 会报出第一帧和差异字段）：

- 影响玩法的随机数一律用 `srand / srandi / spick`（这一局的种子）；`rand / randi / pick`（`Math.random`）只能用在纯画面效果上。
- 模拟里不读真实时间（`Date.now`、`performance.now`），不读设置项、窗口尺寸；联机时画面宽度固定 1280。
- `this.me` 只用于画面、HUD、音效和震动；模拟里的“当前玩家”是 `this.player`（`withPlayer(q, fn)` 切换），找目标用 `nearestPlayer / pickTarget`。
- 新实体的 id 用 `this.eid++`；画面代码（render、HUD）不能改任何玩法状态。
- Build 和资源是每架飞机一份：`this.gun / support / bmod / links / ritual / picks …` 读写的是 `this.player` 那架的（offers.js 顶部的访问器），资源记在 `p.res`；掉落用 `dropPickup`（多人时自动每人一份，`mineDrop()` 只给当前这架）。只给本机看 / 听的表现（音效、横幅、仪式画面、图鉴解锁）用 `this.mine()` 判断，玩法数据不许放在这种判断里面。

**转发层**（`js/net.js`，接口都是“在场状态”：`peers() / presence(patch) / onChange / connected / close`）：

| 环境 | 转发 | 说明 |
|---|---|---|
| 联机服务器提供的网页（`http://服务器:8080/`） | `WsNet`：WebSocket 连 `server/relay.js` | 主力方案。服务器在网页里写入 `window.DREAMTIDE_WS`，网页和连接同源、不需要证书；断线自动重连、身份不变，自己掉线时不会误判别人掉线；也可以用 `?mp=ws://主机:端口/mp` 指定 |
| 在 Claude 里打开的游戏 Artifact | `RoomNet`：Claude Artifact 的 `room` 能力 | 打开同一个链接、已登录的同组织成员互相可见；每人的在场状态 ≤ 4 KiB、约 30 次 / 秒、只保留最新——所以每份状态都带着“别人还缺的那段操作帧”，丢了下一份补上 |
| GitHub Pages / 本地 / 未登录 | `LocalNet`：BroadcastChannel | 只连同一浏览器的多个窗口，用来测试：同一个地址开两个窗口就能进同一个房间 |
| Steam（下一步） | 待做：Steam 大厅 + `ISteamNetworkingMessages`（Electron + steamworks.js） | 实现同一套在场状态接口即可，帧同步和游戏代码不用改 |

标签页切到后台时浏览器会停掉画面刷新，联机由 Worker 计时器（`NetTicker`）继续采操作、跑模拟，队友不用等。

操作延迟 = 网络往返 + 转发路上的等待。转发路上不攒包：采到新操作马上发（`MpDriver` → `Lobby.flush` → `WsNet.sendPending`，两次至少隔 16 毫秒），服务器收到就转发（同一轮事件循环里到的合并成一条），收到就喂给帧同步——本机测得操作从一端到另一端约 12 毫秒（之前固定节拍批量发送时约 100 毫秒）。

**联机服务器**：`server/relay.js` 只转发在场状态、不跑游戏逻辑；同一房间的人收完整状态，房间外的人只收大厅摘要。部署：

1. 让服务器信任部署密钥（在自己的终端运行，会问一次 root 密码）：`ssh-copy-id -i ~/.ssh/dreamtide_ed25519.pub root@服务器`
2. 云控制台安全组放行 TCP 8080 入方向
3. `node tools/deploy-server.js root@服务器`（打包网页 → 装 Node → 上传 → systemd 常驻 → 从本机检查外网能否访问）

联机测试统一用 **http://39.106.153.154:8080/**（另一台 183.87.130.216 也会自动更新，作备用）。

**自动更新（协作者不需要做任何额外的事）**：两台服务器每 2 分钟看一次 GitHub 上 main 的最新提交；这个提交的检查（GitHub Actions 的 check）通过后，服务器下载源码、用低权限用户打包网页并跑服务器自测，都通过才换上——推送到 main 后大约 3~5 分钟，联机网址就是新版本。检查或自测没通过的提交不会上线，线上保持上一个好版本。不需要在仓库里放任何密钥或密码。
- 想确认线上是哪个版本：打开 `http://服务器:8080/health`，`commit` 就是上线的提交，`build` 是网页版本号。
- 网页版本不一样的人进不了同一个联机频道（避免玩法代码不同而不同步）；开着旧网页的人在联机界面会看到“刷新页面”。
- 服务器程序（`server/relay.js`）有改动时会重启一次，正在玩的人约 2 秒内自动重连。
- 服务器上看自动更新日志：`journalctl -u dreamtide-update -n 50`。GitHub Pages（https）连不了 `ws://`，要让 Pages 也能联机，需要给服务器配域名和证书（`wss://`）。

## 协作流程

1. 开工前先同步：`git pull`（等于 fetch + merge；不要用 rebase）。
2. 改动尽量小而集中，一次提交说清一件事；提交说明用中文写“改了什么、为什么”。
3. 推送前在本地跑一遍上面的检查。
4. `git push` 到 main 后，GitHub Pages 大约 1 分钟内自动更新线上版本——**推上去就是对外版本**，没把握的改动可以先开 PR，等检查变绿再合并。
5. 多人同时改 `js/data.js` 或 `index.html` 最容易冲突，动之前在群里说一声。

不要提交：`.ai/`（本地临时区）、`dist/`（打包产物）、`.DS_Store`、`node_modules/`（已写进 `.gitignore`）。

## 约定

- 只做 Steam（键鼠 + 手柄 / Steam Deck）：不做手机适配，也不做商业化运营（付费、广告、战令等）。
- 玩家看到的文字一律中文，一句话说清，不写系统规则长文；代码注释也用中文。
- 机制 / 技能的说明统一写成：图标 + 名字，换行一句话（不写伤害、冷却、百分比这类数值），强弱用箭头——绿色 ▲ 加强、红色 ▼ 削弱，1~3 个表示幅度。数据写在 `js/data.js`（技能的 `lv` 一句话 + `fx` 箭头），网页用 `fxHtml` / `abilityHtml`，画布用 `drawFx`。
- 美术全部是 Canvas 程序化绘制，不引入外部图片和第三方库。
- 改了存档结构，要在 `js/util.js` 的 `Store` 里写迁移，不能让旧存档读坏。
- 数值按关卡固定，不随玩家变强偷偷给敌人加血（联机按人数加厚是公开规则，见上文）。
